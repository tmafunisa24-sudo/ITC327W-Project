## Project Overview

**Project Title:** Planning, Requirements and Feasibility  
**Project Type:** Academic Group Assessment (Software Engineering / Systems Analysis)  

### 📖 Brief Description

This project addresses a stakeholder problem by systematically defining the requirements, scope, feasibility, and risks for a proposed software solution. Through structured stakeholder analysis, functional and non-functional requirements documentation, and a multi-dimensional feasibility study, this project establishes the foundation for a viable system.

The proposed solution leverages modern web and mobile technologies to deliver an accessible, secure, and scalable platform. The project is currently in the **planning and requirements** phase.

---

## 🛠️ Technologies & Stack

The proposed solution is architected using the following technologies:

| Component   | Technology               | Purpose                                                                 |
|-------------|--------------------------|-------------------------------------------------------------------------|
| **Frontend**  | Flutter                  | Cross-platform mobile and web user interface                            |
| **Backend**   | ASP.NET API              | RESTful API services, business logic, and request handling              |
| **Database**  | Supabase (PostgreSQL)    | Relational database with real-time capabilities                         |
| **Auth**      | Supabase Auth            | Authentication and access control                                       |
| **Storage**   | Supabase Storage         | File and asset storage                                                  |

These technologies were selected for their scalability, developer productivity, and alignment with modern cloud-native practices.

## 📌 How to Contribute (Team Guidelines)

1. **Branches:**  
   - `main` – final, stable version
   - `main/docs` - all project documents (SRS, business case, etc ...)
   - `main/docs/stakeholder` - stakeholder documents
   - `main/docs/requirements` - requirements analysis
   - `main/docs/feasibility` - feasibility analysis 
   - `main/docs/risks` - risk register 
   - `main/docs/meetings` - stakeholder meetings
   - `main/docs/architecture` - technical architecture (tech stack) documentation
   - `main/web` - aspnet work
   - `main/mobile` - flutter application work
   - `main/database` - database setup (supabase)
   - `main/testing` - testing & validation
   - `main/project-management` - project management applications & tools
  

2. **Pull Requests:**  
   - All changes must be submitted via pull requests and reviewed by at least one other member.  

3. **Progress Updates:**  
   - Update your row in the **Progress Tracker** (Google Sheets) by every Wednesday.  

4. **Evidence:**  
   - Provide evidence (links, screenshots, or files) for every deliverable.
